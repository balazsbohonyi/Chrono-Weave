What this model leaves out

Left outWhy it matters
Whether a chain is foundThe lab counts work, not success. Triage and mixed batches change which pairs are asked and when, so the real test is requests per success on the reviewed cases.
Delay from filling batches“Mix re-asks, fill before sending” may hold a part-full batch until the next discovery lands, delaying an early exit by up to a round. The model assumes perfect packing and prices none of that, so B's saving is an upper bound. Sending pairs that join the two ends immediately is what limits the delay.
The request lost at a time-outWhen the 180 s deadline aborts a request, its pairs are asked again next segment. Fewer, faster segments lose less.
RetriesValidation and rate-limit retries multiply HTTP calls inside a task (Ollama up to 6, Gemini and OpenRouter up to 12). They cost seconds, not tasks.
Token costDiscovery prompts carry up to 80 reference people. Bigger batches send fewer repeated headers, which this page does not price.
Formulas 
newPairs   = S x C x q x sides          (S=4, C=6; sides = 2 when both ends share a request)
fresh      = min(newPairs, K) + cross + churn   (K only when triage is on; churn only when G is off)
reask      = u x fresh
assess/req = merge ? (fresh + reask) / B
                   : ceil(fresh / B) + max(1, reask / B)
discovery  = rounds / sides          (x 1/recall when triage is on)
total      = seed + identity + other + discovery x (1 + assess/req)
seconds    = total x L  (+ gap per request; assessment part / parallel; reply +0.3 s per pair above 8)
pFail      = 1 - (1 - eps)^B         (a reply with any bad item)
abort      = 1 - (1 - pFail^2)^assessRequests   (two bad replies in a row; 0 with D)
